# Local observability stack

The local overlay adds the complete telemetry stack to the normal application
Compose stack. It is opt-in: `docker compose up` keeps its default behaviour.

```bash
make observability-init       # generate the local Grafana admin password
make observability-up         # start app + Prometheus, Loki, Tempo, Grafana, ...
make observability-smoke-test # generate traffic and validate every signal
```

The equivalent explicit command (run the init first) is:

```bash
docker compose -f docker-compose.yml -f docker-compose.observability.yml up -d --build
```

The stack publishes every UI and API on **127.0.0.1** by default. Nothing is
exposed publicly.

## Prerequisites

- Docker Compose v2, or a Docker-compatible API.
- `make`, `curl`, `jq`.
- The application secrets from the root `.env` or the environment.
- The judge's rootless Podman socket for submissions to run.
- For the browser test: Playwright Chromium installed once with
  `cd frontend && bun run test:e2e:install`.
- For the authenticated submission test: an admin password bootstrapped with
  `database/bootstrap-admin.sh`, exported as `SMOKE_ADMIN_PASSWORD`.

`/healthz`, which is what the Docker health check uses.

## Application telemetry variables

The overlay sets the standard OpenTelemetry variables on both Go services:

| Variable | Value | Meaning |
| --- | --- | --- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://otel-collector:4318` | enables export |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/protobuf` | OTLP/HTTP |
| `OTEL_SERVICE_NAME` | `runcodes-backend` / `runcodes-judge` | `service.name` |
| `DEPLOYMENT_ENVIRONMENT` | `development` | deployment environment |
| `OTEL_SERVICE_VERSION` | `dev` | service version |
| `OTEL_TRACES_SAMPLER` | `parentbased_always_on` | deterministic smoke test |
| `OTEL_TRACES_SAMPLER_ARG` | `1.0` | ratio for ratio samplers |
| `OTEL_SDK_DISABLED` | `false` | standard kill switch |
| `OTEL_METRIC_EXPORT_INTERVAL` | `10000` ms | metric export cadence |
| `OTEL_BSP_SCHEDULE_DELAY` / `OTEL_BLRP_SCHEDULE_DELAY` | `2000` ms | span/log batch delay |
| `PPROF_ADDR` | `:6060` | internal pprof listener for Alloy |

Browser build variables:

| Variable | Local value | Meaning |
| --- | --- | --- |
| `VITE_OTEL_ENABLED` | `true` | opt in to browser tracing |
| `VITE_OTEL_EXPORTER_OTLP_ENDPOINT` | `http://localhost:4318` | browser-reachable collector |
| `VITE_OTEL_SERVICE_NAME` | `runcodes-frontend` | browser `service.name` |
| `VITE_OTEL_TRACES_SAMPLER_ARG` | `1.0` | browser sampling |
| `VITE_DEPLOYMENT_ENVIRONMENT` | `development` | browser environment |

Browser variables are baked in at **build time**: rebuild the frontend after
changing them.

| Variable | Default | Meaning |
| --- | --- | --- |
| `OBSERVABILITY_BIND_ADDRESS` | `127.0.0.1` | host interface for published ports |
| `GRAFANA_ADMIN_USER` | `admin` | Grafana login |
| `GRAFANA_ADMIN_PASSWORD` | generated file | read from `.observability/grafana_admin_password` |
| `GRAFANA_ROOT_URL` | `http://localhost:3000` | links generated by Grafana |
| `GRAFANA_PORT`, `PROMETHEUS_PORT`, `ALERTMANAGER_PORT` | `3000`, `9090`, `9093` | overrides |
| `LOKI_PORT`, `TEMPO_PORT`, `PYROSCOPE_PORT`, `ALLOY_PORT` | `3100`, `3200`, `4040`, `12345` | overrides |
| `OTEL_GRPC_PORT`, `OTEL_HTTP_PORT`, `OTEL_HEALTH_PORT` | `4317`, `4318`, `13133` | overrides |
| `OTEL_METRICS_PORT`, `OTEL_PROM_PORT` | `8888`, `8889` | collector metrics |
| `NODE_EXPORTER_PORT`, `POSTGRES_EXPORTER_PORT`, `REDIS_EXPORTER_PORT` | `9100`, `9187`, `9121` | exporters |
| `BLACKBOX_EXPORTER_PORT`, `ALERT_SINK_PORT` | `9115`, `8085` | exporters |
| `FRONTEND_OTEL_ENABLED`, `PUBLIC_OTEL_HTTP_URL` | `true`, `http://localhost:4318` | browser build inputs |
| `PROMETHEUS_RETENTION_TIME` / `_SIZE` | `15d` / `8GB` | TSDB guardrails |
| `PYROSCOPE_CONFIG_FILE` | `./observability/pyroscope/config.yaml` | alternate Pyroscope config |
| `ALERTMANAGER_CONFIG_FILE` | `./observability/alertmanager/alertmanager.yml` | Alertmanager config; point it at a copy of the Gmail example to email alerts |

The Grafana password is generated by `scripts/observability/init-secrets.sh`
into `.observability/` (gitignored) and mounted as a read-only file. It is not
stored in `.env`, Compose or an image layer. The Alertmanager webhook URL and
the optional Gmail app password live in `.observability/alertmanager_webhook_url`
and `.observability/alertmanager_gmail_app_password`.

### Gmail notifications

To email alerts through Gmail, copy
`observability/alertmanager/alertmanager.gmail.example.yml` to
`.observability/alertmanager.yml`, set the sending account and recipients, write
a Google app password to `.observability/alertmanager_gmail_app_password`, and
set `ALERTMANAGER_CONFIG_FILE=./.observability/alertmanager.yml`. Gmail requires
2-Step Verification and an app password (not the account password). The
[runbook](./runbook.md#configuring-gmail-notifications) has the full procedure.

## Running a service outside Compose

The backend and judge are no-ops unless an endpoint is set. To run one locally
against the collector:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_SERVICE_NAME=runcodes-backend
export DEPLOYMENT_ENVIRONMENT=development

cd backend && go run . -debug
```

The collector publishes 4317/4318 on loopback, so a host process can send
telemetry without joining the Compose network. `OTEL_SDK_DISABLED=true` turns it
off again.

## Validation

```bash
# Static: compose, promtool, amtool, collector validate, JSON/shell checks
make observability-validate

# End to end: starts/validates the stack and generates real traffic
make observability-smoke-test

# Real Chromium trace
make observability-browser-smoke-test

# Authenticated submission + per-case span + span-to-profile bridge
SMOKE_ADMIN_PASSWORD='...' make observability-submission-smoke-test
```

The static check also validates the Gmail and production receiver examples with
`amtool check-config`, so a malformed receiver fails before the stack starts.

The smoke test checks:

1. every service is reachable (starts the stack when `SMOKE_START=1`);
2. a backend request returns a 32-hex `TraceId`;
3. Prometheus has backend and judge HTTP metrics and the collector target is up;
4. Loki returns backend logs with the smoke id, judge logs, and the exact
   trace's log line;
5. Tempo stores the exact trace id from the response header;
6. the judge queue metric exists, Pyroscope has profiles, and Alloy/Pyroscope
   targets are up;
7. the collector accepts a browser-origin OTLP span and Tempo stores the
   `runcodes-frontend` trace (CORS + browser data path);
8. Grafana's Prometheus/Loki/Tempo/Pyroscope datasources are healthy, the
   Alertmanager proxy works, and the `runcodes-overview` dashboard exists;
9. Alertmanager delivers an injected alert to `alert-sink`.

The browser test additionally asserts that a real fetch carries `traceparent`
and that the same trace contains both frontend and backend spans. The submission
test asserts the judge's `judge.grade_test_case` span, its verdict, and the
`pyroscope.profile.id` attribute.

Expected output ends with `All observability smoke checks passed.` and lists the
service URLs, the trace id and elapsed time. On failure the script prints
`docker compose ps`, the last 40 lines of each service log and the last API
responses.

## Start, stop and destroy

```bash
make observability-status
make observability-logs
make observability-down      # keeps telemetry volumes
make observability-destroy   # removes observability volumes only; prompts
FORCE=1 make observability-destroy
```

`observability-destroy` never touches the application database or SeaweedFS
volumes. It removes Prometheus, Loki, Tempo, Grafana, Alertmanager, Pyroscope
and Alloy data.

## Rebuilding after a telemetry change

Browser variables are compile-time, and the collector/Grafana configs are mounted
files:

```bash
make observability-up       # rebuilds the instrumented images
```

For a backend-only telemetry change, `docker compose ... up -d --build backend`.
For a collector config change, recreate the collector. For a Grafana provisioning
change, restart Grafana (a provisioning error intentionally fails startup).
